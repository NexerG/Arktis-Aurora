# Project file structure

The layout a project built on the Aurora engine follows. `Thorium/` is the reference; `Carbon/` is the smallest
complete example. What is specific to one project lives in that project's `README.md`, not here.

## Placement

A project folder is a **sibling of `AuroraEngine/`**. Two things depend on it:

- In Debug, `Paths` mounts the project's own `Data/` first and `../AuroraEngine/Data` below it. The project
  inherits every engine default without copying it, and a file at the same path in its own `Data/` overrides it.
- In Debug, data paths resolve from `bin/<config>/<tfm>/../../..` — the project root. `Data/` and `Shaders/`
  therefore sit at the root, not in a subfolder.

## Tree

```
<App>/
├── <App>.csproj            ProjectReference to ..\AuroraEngine\AuroraEngine.csproj; copies Data\**\*.* to output
├── <App>.cs                entry point — Main, below
├── <App>Settings.cs        the project's own settings type
├── <App>.build.axml        shipping recipe (aurora-ship skill)
├── README.md               what Claude needs to know about this project
├── NAMESPACES.md           only when the project is its own repository (_Build/GenerateNamespaces)
├── test-baseline.txt       errors Boot is known to log (aurora-test skill)
├── Editor/                 project code, namespace <App>.Editor.*
│   └── CustomControls/     the project's own Control subclasses, <App>.Editor.CustomControls
├── Tests/                  the project's test suites
├── Shaders/                copy of the engine's shaders (shader-pipeline skill) — never edited here
└── Data/
    ├── Fonts/<name>/       cooked fonts
    ├── Icons/<set>/        cooked icon sets
    ├── UIMasks/            mask images
    ├── Scenes/
    └── XML/
        ├── Assets/         <App>Assets.assets.axml — the project's asset manifest; registers the root
        │                   window as UIDocumentAsset "main" → XML/Documents/UI/UI.ui.axml
        ├── Settings/       *.settings.axml — project defaults; user overrides are written elsewhere
        ├── Schemas/        generated by XSDGenerator on every run — never edited
        └── Documents/
            ├── UI/         *.ui.axml — windows and panes; UI.ui.axml is the root window
            ├── Inputs/     keybind maps, one keybind group per file
            ├── Menus/
            ├── Palettes/
            ├── Contexts/
            ├── Animations/
            ├── Effects/
            └── Tests/
```

Only the folders a project uses need to exist.

## Rules

- **Data files are `[name].[type].axml`.** The name half has no dot; the type half picks the schema.
- **Override, don't edit.** To change an engine default for one project, put a file at the same path under the
  project's `Data/`. Editing `AuroraEngine/Data` changes it for every project.
- **Engine-owned documents stay in the engine** — `Bootstrap.bootstrap.axml`, `Shutdown.shutdown.axml`,
  `Frame.frame.axml`, `Registry.registry.axml`, `Pools.pools.axml`. A project overrides one only when it needs a
  different sequence.
- **`Shaders/` is a mirror.** Edit `AuroraEngine/Shaders`, compile, then copy (shader-pipeline skill).
- **Project code never reaches into another project.** Shared code moves into the engine.

## Main

```csharp
static void Main(string[] args)
{
    Engine engine = new Engine();
    XSDGenerator.GenerateXSD();

    SettingsRegistry.SetWriteRoot(Path.Combine(
        Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData), "Arktis", "<App>", "Settings"));

    engine.Init(false);
    InputHandler.SetActiveKeybindGroup("InputMap");

    WindowRoot root = (WindowRoot)Control.ParseXML("main");
    Engine.primary.uiDocument = "main";
    Engine.primary.ui.uiRoot = root;

    engine.Run();
}
```

## Existing projects that differ

Known departures. Don't normalise them unasked.

| Project | Differs in |
|---|---|
| `AuroraEditor` | code lives in `EditorProgram/`, not `Editor/`; no `Data/XML/Settings/`, no `Tests/` |
| `Carbon` | `Carbon.csproj` copies only `Data/UIMasks` to output; no `Tests/`, no `.build.axml`; `Shaders/` carries only the UI path |
| `Thorium` | its own repository, so it carries `NAMESPACES.md`; extra `Startup.cs` beside the entry point |
