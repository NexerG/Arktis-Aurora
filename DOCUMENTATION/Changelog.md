- [x] **UI Engine landing 3 — input (2026-09-06)** — the new stack answers the pointer. `UIEngine.Poll` runs at the top of `Engine.HandleUI`, ahead of that method's own guards so the pointer *leaving* a window still clears a hover — scoped to the polling window's own tree, since every window polls and the contexts are global. `HitTest` is a `subtreeBounds` early-out, then the node's own `clip` and `arranged`; `Dispatch` is one walk from the hit control up through its parents until a handler returns `true`, and **every phase goes through it, enter and exit included**. `PointerEvent` carries the control actually under the pointer, so an ancestor handling a bubbled event knows what was hit. **Hover is one control, not a chain** — hovering a glyph does not make its document, its panel and the window root "hovered"; ancestors hear about it only because the event bubbles, which is exactly what lights a button when the pointer is over its label. - [x] **UI Engine landing 5 — images, icons, masks and gradients (2026-09-06)** — the third quad kind and the gradient table arrive, and **no struct changed**: `uvs`, `textureIndex` and `gradientIndex` were already in `VulkanControl` and `gradientRect` already in `ControlGeometry`, all written by nothing since landing 1, so the row sizes are still 140 / 96 / 92 and neither `scalar` stride moved. `Control` grew `kind`, `sampler`, `gradient` and `SetUVRect`, the last of which is the one place that knows the quad mesh's vertex order is `(u1,v1),(u0,v0),(u0,v1),(u1,v0)` and not a min/max pair. **One sampler slot whose meaning `kind` selects** — the distance field on a glyph or icon, a coverage mask on a panel, the colour source on an image — which is the same answer the merged `edge` pair took, for the same reason: three slots each with one consumer is worse than one with three readings. The price was taken knowingly and is that **an image cannot also carry a mask**; the fix is a second index plus a second UV set, which grows the 92 B row that a paragraph holds several hundred of. "No texture" is `uint.MaxValue`, **not** a reserved slot 0 — gradients could reserve slot 0 because one loader builds that table, but the texture table fills in asset-load order and slot 0 is `defaultMask.png`, a real texture the outgoing stack still resolves `maskAsset = null` to, so reserving it would have meant a null texture, a change to `TextureAsset` and a behaviour change in the stack being deleted. Named `sampler` by the user over `texture` and `maskAsset`, both of which name one of the three readings; `SamplerAsset` and `Silk.NET.Vulkan.Sampler` already exist in the same render path, which is a readability collision and not a C# one. **The mask multiplies last, after the edge band**, so a masked control is one silhouette and its border follows the mask instead of floating around it as the rounded rectangle it would otherwise be. The gradient table returns at **set 1 binding 3** — the numbering the old shader already uses, so nothing renumbered — with `sampleGradient` copied verbatim from `UIRasterizer/UI.frag`, whose 184-byte layout is already proven against C# `GpuGradient`; the buffer is a **static** on `UIEngineModule`, built once in `PrepareObjects` and never freed, because the table is per-process and destroying it with one window would dangle every other window's descriptor.
